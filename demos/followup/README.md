# Follow-up R1–R8: offline experiments and D01b adapter

From `demos/followup`, run `python run_r8_regression.py` for the current seven suites including R8 corrections to R6/R7. This directory is a demo/evidence tree, not a production package. R1–R3 are imported byte-for-byte from their previously archived bundles; R4–R5 source is preserved, including original results. R1–R4 hash inventories are checked before the isolated suite runs. R6 introduces a read-only adapter and experimental candidate-plan export. D01b PR #4 remains authoritative for actual checkpoint loading, pruning and execution. No dependency on downloaded model weights for these tests.

## R6 compatibility and restrictions

Reviewed D01b snapshot: `93a6637ff2c231140d8d2abcbf18822da9f70498`; `calibration.py` blob `1abfb4c485356ca6b77705ebc255b59cc3bf9683`, `pipeline.py` blob `671ce02eea36287de44256eb4e3ee0508e754996`, `report.py` blob `9b20a3aff5cc3e2da49ff124b0da0929de977de8`. Corpus: D01b's frozen FLORES-200 (not R1's alternative FLORES+ acquisition path). D01b directions are explicitly ordered, not sorted. The adapter checks corpus hash, calibration IDs, sample counts, prompt/decode lengths, layer IDs, per-phase counts and masses. It refuses empty phases, missing groups, masked runs, malformed shapes, missing mass, and inconsistent aggregate coverage. It is not a cryptographic provenance check: the caller must bind the actual teacher and complete run identity, ensure artifacts are immutable while reading, and verify per-sample statistics persistence. A fresh corrected D01b calibration receipt is required before actual use. No real artifacts have been consumed here.

`r6/prepare_candidates.py` produces D01b-compatible selection JSON (`candidates[keep].kept[layer]`) for phase-balanced, worst-first or seeded random plans. It does not execute or modify D01b and cannot claim quality. Use only with reviewed source and a distinct output path. D01b's original selection method sums prefill and decode then balances directions; R6's phase-balanced method is deliberately different and must be treated as an experimental candidate. D01b's physical adapter owns the actual layer mapping, reload and mechanism checks. Do not use aggregate-only data to infer per-token coactivation, saliency or stability. `r6/bridge.py:quality_gate` independently calculates report-level delta >= -max_drop and per-direction diagnostics; raw evaluation IDs, actual source identity and held-out protocol still require separate verification. No aggregate-only or report-only PASS qualifies production quality.

## R8 scoped corrections

R7 checks normalized text across all languages using D01b normalization order (NFKC, whitespace, casefold). The declared sampled-line duplicate rule is conservatively enforced across all selected distinct lines within a split as well as across splits; repeated language/direction text on the same parallel line is allowed. If the actual frozen corpus fails, stop and report, never resample retroactively. Actual corpus bytes remain unverified. The only accepted decoding header is `greedy (argmax of bf16 logits)`; it does not prove actual execution. R6 validates sparse diagnostic keys against the seven D01b flags; absent keys inside an explicit map mean zero, absent maps are rejected. Only three flags gate the provisional quality decision. R7 selection remains provisional and final-test authorization remains false.
