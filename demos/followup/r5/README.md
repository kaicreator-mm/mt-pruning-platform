# R1–R5 consolidated offline demo bundle

Run `python run_regression.py` from this directory. R1–R4 are the original archived bytes, hash-verified; each suite runs in an isolated process. This is source packaging and regression, not a unified runtime API. Python 3.13.5, torch 2.10.0+cpu, safetensors 0.7.0; 74 tests pass and 17 files compile. Real datasets, external pretrained checkpoint, actual Hy-MT3, GPU and GGUF remain outside these tests. D01b PR #4 is the authoritative real adapter; do not substitute these prototypes for it.

R5 cache_plan.py: seven SHA256 identity components and explicit split, immutable completed receipts, verifies artifact hash on lookup. Caller must construct hashes from complete provenance, prove coverage and enforce held-out access; cache does not prove metrics or skip a real runner automatically. Disk planner uses reviewed exact unquantized payload inventory, per-layer counts and top-k, estimates one candidate at a time (no physical dedup or deletion implemented). Reserve is user-supplied; conversion intermediates, sidecars and overhead need separate accounting. No model bytes shared or overwritten.

D19 recovery.py: three fixed seeds, generated classification task, train/calibration/recovery/test sizes 640/192/256/192. Same pruned starting model, 100 router-only KL steps; assert all other parameters unchanged. Pruned test correct 173/169/167, recovered 171/158/165. KL worsened in all three. Negative result for this recipe; defer real recovery, no universal claim. No separate recovery validation or tuning; fixed exploratory protocol only.

D20: do not prune tokenizer for initial release. Removing tokens or remapping IDs risks input segmentation, target generation, embedding/lm_head alignment, special tokens and chat templates. If revisited, separately measure tokenizer frequency on all six directions, preserve byte/character fallback and special IDs, validate exact tokenization and decoding, embedding/tied-head alignment, quality and measured size reduction.
